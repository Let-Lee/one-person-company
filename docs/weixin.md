# 微信连接

微信是公司现有经理的消息入口，不新增模型、经理或外部会话写入者。

## 连接

1. 先建立独立团队的总经理，或连接已有 Codex 桌面聊天。
2. 打开“连接设置”，在“微信”中选择当前模式下已有的经理，点击“生成连接二维码”。
3. 本人用微信扫描，并在手机上确认。若微信要求验证码，请本人在页面输入手机提示的验证码。
4. 连接后，给该微信对话发一条文字。页面分别显示连接、收到来信、执行和微信回传状态。

二维码过期可重新生成。网络暂断可点击“重新连接”；认证失效需要重新扫码。点击“断开微信”会清除本机渠道凭据并停止接收，已经存在的任务、运行和结果保留。更换经理前须处理原队列，避免消息投到别的会话。

## 消息与结果

仅接收二维码响应中确认的本人身份，且必须发给当前机器人；群聊、机器人回声、其他来源和没有唯一消息 ID 的内容不执行。支持 1 至 6000 字的文字私聊，其他格式会明确提示，首期不下载图片、语音或文件。

消息 ID 无损保存，消息和游标先持久化再执行。重复接收、重连和服务重启不重新创建已经提交的任务。提交结果不明时保留“待核实”，不会自动重派。经理忙时排队，恢复后仍走原稳定会话与原 Skill、权限和审批设置。

独立团队的任务来源按原经理运行、员工任务与收件箱回合关联。员工阻碍、需决定、经理验收和后续汇总回到对应微信请求；普通进度只记录。若经理同一轮合并了无关网页任务，微信只提示查看本任务或回传能独立关联的任务摘要，不复制其他任务混合正文。

桌面模式使用原桌面聊天持有端的消息入口，不启动另一套 app-server 或抢占会话。自动回传可用的本条消息关联回复；无法可靠关联的其他原生异步回合保留在原聊天/网页，不根据时间猜测所属任务。桌面当前回合的暂停、停止和审批仍在 Codex 操作。

| 微信命令 | 行为 |
| --- | --- |
| `/状态` | 查看队列状态，不调用模型 |
| `/结果` | 用本条新来信的上下文返回最近结果，不重复执行业务 |
| `/暂停` | 暂停渠道待办；独立团队中与本入口关联的当前运行/员工任务按原规则暂停 |
| `/停止` | 取消渠道待办；独立团队关联任务按原取消规则停止 |
| `/继续` | 恢复队列接收；不擅自重启已停止的原任务，原任务在网页明确续办 |

## 回传边界

每个回复保存原来信的 `context_token` 关联和稳定的客户端消息 ID。发送是否成功单独记录；服务器拒绝、认证失效、网络超时或发送中重启均不会被当作“已送达”。失败或送达不明的回复不无限重发；可以在网页查看原任务，或由本人发送 `/结果` 使用新的来信上下文查询。

较长回复分段发送；超过微信入口的展示上限会注明到网页查看全文。前一段没有确认送达时，后续片段保留。发送成功只表示 iLink 接口接受，不证明本人已经阅读。

电脑和本机公司服务须保持运行。凭据与回复上下文只存在本机 `YEWANG_DATA_DIR/channels/weixin/credentials.json`，不进入模型输入、公开源码或诊断正文；私有目录权限为 0700、文件为 0600（Windows 使用账号文件权限）。队列、执行与发送记录在同目录的 `journal.json`。不要共享这两个文件。

## 验证范围

2026-10-15 的 2.1 开发验证：真实未认证二维码接口返回二维码；隔离替身覆盖扫码过期、本人输入验证码、身份过滤、去重、同一会话、网页忙碌排队、重启恢复、提交未知、回传失败、原任务后续回报和混合任务不串回。浏览器页面另外核对亮色、暗色与窄屏。

**本人账号尚未扫码，真实账号收发、账号适用范围及长任务延迟回传仍待本人账号实测。** 腾讯协议文档根据客户端实现整理，不是完整服务端保证。没有固定发送配额或永不失联的承诺。
