# 任务和模型显示

任务页的一行是一件业务事项。展开后先看子任务，再看执行、沟通、回报与验收记录；原始需求、运行 ID 和详情保留。首页、导航计数和任务筛选使用同一事项口径，不为归并调用模型。

归并只使用记录里的 `task.origin.runId`、`run.teamTaskId`、`run.managerMessageIds` 与消息任务 ID。明确“续办”的新运行保存 `parentRunId`。同一会话、标题相似或时间接近不代表同一目标。旧记录缺少关联时保守分列；一个经理回合处理多个事项时，处理记录可在多个事项下查看，不把目标合在一起。

子任务的阻碍、待决定、暂停、待验收会上浮显示。经理派单回合完成不代表业务事项完成。展开状态和列表位置保存在当前浏览器会话中；原数据不作批量迁移或改写。

岗位名后的模型标签只采用逐轮运行元数据：独立运行使用 `turn/start` 或 `turn/started` 返回的模型与相同 turn ID；桌面经理使用当前/最近已执行回合自身的模型元数据。空闲显示“上次”。历史记录不反填默认模型；从未执行显示“未运行”，缺来源或运行端未提供逐轮字段显示“待确认”。悬停可看完整标识和来源，不根据路由标识推断供应商实际底模。

会话默认配置、请求参数、模型列表和回复正文均不单独作为实际模型证明。某些 Codex 运行端不返回逐轮模型字段，这些运行会保持“待确认”；界面不会为获取标签额外启动任务。桌面逐轮参数来自持有端返回的实际回合记录，与全局默认设置区分。

会话消息区与输入区分别布局；执行中可以先写下一条草稿，当前回合结束后再发送。流式更新只刷新消息区，保留输入、焦点和阅读位置。岗位职责全文仍在岗位配置中查看。
